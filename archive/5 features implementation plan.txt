Implementation Plan: 5 Features                        

Context

Five new features for the Shavtzak app: (1) search in assignments screen, (2) same-day event conflict detection, (3)
calendar constraint color fix, (4) event-to-Google Calendar sync, (5) repeating constraints. These are independent features
that can be implemented in sequence.

Implementation Order

1. Feature 3 (trivial color change)
2. Feature 1 (search - self-contained UI)
3. Feature 2 (same-day conflict - BLoC + UI)
4. Feature 4 (event calendar sync - follows existing pattern)
5. Feature 5 (repeating constraints - most complex, all layers)

Feature 2: Same-Day Event Conflict Detection

Members assigned to another event on the same day(s) should appear in "שובצו כבר" section (still assignable with
force-assign). Applies to both the admin assignments dropdown AND the manual assignment flow dialog.

Files to Modify

- shavtzak/lib/presentation/screens/assignment/models/assignment_slot.dart — new fields
- shavtzak/lib/presentation/bloc/assignment/assignment_bloc.dart — slot building logic
- shavtzak/lib/presentation/screens/assignment/assignment_list_screen.dart — display in dropdown/dialog
- shavtzak/lib/presentation/screens/assignment/manual_assignment_flow_dialog.dart — step 2 warning

AssignmentSlot Changes (assignment_slot.dart)

Add fields:
final List<TeamMember> sameDayAssignedMembers; // assigned to OTHER events on same day(s)
final Map<String, List<String>> sameDayEventInfo; // memberId → other event names
Add to constructor (defaults: const [], const {}), add to props.

Assignment BLoC Changes (assignment_bloc.dart)

In the slot-building logic (both _onRebuildAssignmentSlotsFromData and _buildSlotsFromAssignments):

1. After computing assignedMemberIds for the current event, iterate ALL assignments
2. For each assignment to a DIFFERENT event, check if that event's date range overlaps with current event's date range (use
same-day comparison: normalize to day precision)
3. If overlap found AND member has the role capability AND passes availability checks AND !allowMultipleAssignments → add
to sameDayAssignedMembers map
4. Remove same-day members from availableMembersMap (they shouldn't appear as freely available)
5. Pass new fields to AssignmentSlot constructor

Already-Assigned Dialog Changes (assignment_list_screen.dart)

- Merge slot.alreadyAssignedMembers + slot.sameDayAssignedMembers in _showAlreadyAssignedDialog
- For same-event members: show "תפקידים: ..." (existing)
- For same-day members: show "משובצ/ת ב: " (new subtitle)
- Both remain force-assignable via "שבץ בכל זאת"

Manual Assignment Flow (manual_assignment_flow_dialog.dart)

In step 2 (team member selection), after event is selected:
1. Compute same-day assigned member IDs from all assignments + events available in BLoC state
2. Show warning icon/indicator for same-day members in the list
3. On tap, show warning dialog similar to constraint warning: "חבר/ת צוות זה/זו משובצ/ת לאירוע אחר באותו יום: " with "שבץ
בכל זאת" option

Date Overlap Helper

Reuse Event.occursOn() (already exists at event.dart:54) for checking if events share dates:
bool eventsShareDate(Event a, Event b) {
 for (var d = a.startDate; !d.isAfter(a.endDate); d = d.add(Duration(days: 1))) {
   if (b.occursOn(d)) return true;
 }
 return false;
}

- shavtzak/lib/presentation/bloc/calendar_sync/calendar_sync_bloc.dart — new handlers

GoogleCalendarService New Methods

- createAppEventCalendarEvents(...) → creates 2 events:
 a. "<name> - התייצבות והכנות" from assemblyTime→actualShowStartTime on event startDate
 b. "<name>" from actualShowStartTime→endTime on event startDate (endDate for multi-day)
 - Returns Map<String, String> with 'assembly' and 'main' calendar event IDs
 - Uses time-based events (not all-day): EventDateTime(dateTime: combinedDateTime)
 - Test mode: yellow color + "שבצק טסטינג: " prefix
- updateAppEventCalendarEvents(...) → updates existing calendar events
- deleteAppEventCalendarEvents(...) → deletes both calendar events (handles 404/410)
- Helper: _combineDateTime(DateTime date, String timeHHmm) → combines date + time string

Firestore Sync State

Collection: ${collectionPrefix}event_calendar_sync (doc ID = eventId)
Fields: assemblyCalendarEventId, mainCalendarEventId, status, lastSyncedAt, retryCount, errorMessage

CalendarSyncBloc New Events

- SyncAppEventToCalendar(Event event) — create or update
- RemoveAppEventFromCalendar(String eventId) — delete

EventBloc Integration

- In _onCreateEvent: after success, access CalendarSyncBloc and dispatch SyncAppEventToCalendar
- In _onUpdateEvent: after success, check if date/time fields changed → dispatch SyncAppEventToCalendar
- In _onDeleteEvent: before/after delete, dispatch RemoveAppEventFromCalendar
- The EventBloc will need a reference to CalendarSyncBloc (pass via constructor, or use context from UI layer via
BlocListener)

Edge Cases

- Missing time fields: if assemblyTime/actualShowStartTime/endTime empty → skip creating that calendar event (or create
all-day event as fallback)
- Multi-day events: assembly event on startDate, main event spans startDate→endDate
- Event update: compare old vs new event to determine if sync needed (only if date/time fields changed)

Feature 5: Repeating Constraints

New constraint type for permanent members with recurring unavailability patterns (daily/weekly/monthly).

Files to Modify

- shavtzak/lib/core/constants/constraint_status.dart — add RepeatType enum
- shavtzak/lib/domain/entities/team_member.dart — extend DateConstraint entity
- shavtzak/lib/data/models/team_member_model.dart — extend DateConstraintModel serialization
- shavtzak/lib/presentation/screens/user/constraints_screen.dart — UI flow (prior dialog + repeating dialog + confirmation)
- shavtzak/lib/presentation/screens/team/team_list_screen.dart — admin constraint card indicator

RepeatType Enum (constraint_status.dart)

enum RepeatType { daily, weekly, monthly }
With hebrewName extension: 'יומי', 'שבועי', 'חודשי'.

DateConstraint Entity Changes (team_member.dart)

New fields:
final RepeatType? repeatType;      // null = one-time, or daily/weekly/monthly
final int? repeatDay;              // weekday (1-7, Mon=1) for weekly; day-of-month (1-31) for monthly; null for daily
final DateTime? repeatEndDate;     // required for repeating constraints
Add to constructor, props, copyWith (with clearRepeatType/clearRepeatDay/clearRepeatEndDate booleans).

Update conflictsWith(DateTime date):
if (repeatType != null) return _matchesRepeatPattern(date);
// ... existing one-time logic ...

New method _matchesRepeatPattern(DateTime date):
- Check date is within startDate..repeatEndDate range
- RepeatType.daily → always true within range
- RepeatType.weekly → date.weekday == repeatDay
- RepeatType.monthly → date.day == repeatDay

Update toString() for repeating constraints to show pattern description.

Note: blocksEventAssignment(Event) already works since it checks time overlap — repeating constraints' time fields work the
same way.

DateConstraintModel Changes (team_member_model.dart)

New fields: repeatType (String?), repeatDay (int?), repeatEndDate (DateTime?)

- fromEntity(): convert RepeatType enum to string name
- toEntity(): parse string back to RepeatType enum
- fromJson(): read from Firestore with null defaults (backward compat)
- toJson(): write to Firestore (null values handled gracefully)
