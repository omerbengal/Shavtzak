## Change 1: Conversation-Like Notes System for Checklist Items (הערות שיחה)

### Scope
Transform single-note checklist items into a conversation-like notes system where multiple notes can be added over time, preserving history.

### Entity Changes

**New: `lib/domain/entities/checklist_note.dart`**
```dart
class ChecklistNote extends Equatable {
  final String id;
  final String content;
  final DateTime createdAt;
  final String createdByTeamMemberId;  // Who wrote this note
  final String? createdByTeamMemberName; // Denormalized for display
}
```

**Modify: `lib/domain/entities/checklist_item.dart`**
- Remove: `final String? note;` (single note field)
- Add: `final List<ChecklistNote> notes;` (array of notes)
- Add method:
```dart
String? get latestNoteContent {
  return notes.isEmpty ? null : notes.last.content;
}
```

### Data Layer

**New files:**
- `lib/data/models/checklist_note_model.dart` - Firestore serialization for ChecklistNote

**Modify:**
- `lib/data/models/checklist_item_model.dart` - Change from `note` field to `notes` array
- `lib/data/data_sources/database_interface.dart` - Update checklist item methods
- `lib/data/data_sources/firestore_database.dart` - Store notes as array in checklist item document
  - Each note in array: `{id, content, createdAt, createdByTeamMemberId, createdByTeamMemberName}`
  - Or store as subcollection: `checklistItems/{itemId}/notes/{noteId}` (choose based on query needs)

**Modify:**
- `lib/data/repositories/checklist_repository.dart` - Add `addNoteToChecklistItem()` method
```dart
Future<void> addNoteToChecklistItem({
  required String checklistItemId,
  required String content,
  required String teamMemberId,
  required String teamMemberName,
});
```

### BLoC Layer

**Modify: `lib/presentation/bloc/checklist/`**
- `checklist_event.dart`: Add `AddChecklistNote` event
- `checklist_bloc.dart`: Handle adding notes to checklist items

### UI Changes

**Modify: `lib/presentation/widgets/checklist/checklist_item_card.dart`** (or user view variant)
- Replace single note display with chat-like interface:
  - Show most recent note prominently
  - "View all notes" button to open notes history
  - "Add note" button to append new note (instead of overriding)

**New: `lib/presentation/widgets/checklist/checklist_notes_modal.dart`**
- Modal/dialog showing full notes conversation
- Chat-like UI with:
  - Timestamp for each note (Hebrew date format)
  - Author name for each note
  - Newest notes at bottom
  - Input field at bottom to add new note
  - Auto-scroll to newest note on open
- Read-only display for historical notes (no editing/deleting)

**Modify: `lib/presentation/widgets/checklist/checklist_form_modal.dart`**
- Update note input to indicate it will add a new note (not replace existing)

### UI Behavior
- Checklist item cards show snippet of latest note (first 50 chars + "...")
- Clicking note snippet opens full notes conversation modal
- Adding new note appends to `notes` array (preserves all previous notes)
- Notes sorted chronologically (oldest first, newest last)
- Each note shows who wrote it and when
- Notes are permanent - no editing or deleting (keep audit trail)

        },
        {

## Change 2: Admin Screen Titles Truncated on Phone (הכותרות במסכי אדמין בטלפון)

### Problem
On phone-sized devices, the admin screen titles (events, assignments, checklist) are truncated/cut off because the AppBar icon buttons consume too much horizontal space, leaving insufficient room for the title text.

### Scope
Fix the AppBar layout in admin screens that have icon buttons (leading and/or actions) so that:
1. Titles are never truncated on phone-width screens
2. Padding between icon buttons is slightly reduced to reclaim space
3. The title text is always visually centered between the leading icons and the trailing icons

### Files to Modify
- `lib/presentation/screens/event/event_list_screen.dart` — AppBar has leading icons (search, filter) and action icons (role mgmt, category mgmt, home, logout)
- `lib/presentation/screens/assignment/assignment_list_screen.dart` — AppBar has a wide leading container (250px) with past-events toggle + filter icon, and action icons (home, logout)
- `lib/presentation/screens/admin/checklist_screen.dart` — AppBar has leading filter icon and action icons (home, logout), plus a bottom TabBar

### Changes
- Reduce horizontal padding/margins between adjacent icon buttons in the AppBar (make spacing slightly tighter)
- Ensure the title widget uses `Expanded` or `Flexible` with `TextOverflow.ellipsis` as fallback but primarily ensure there's enough room by reducing icon spacing
- Center the title text between the leading and actions groups — if the leading group is wider, add balancing invisible spacer on the actions side (or use `centerTitle: true` with proper flex layout)
- Consider using `titleSpacing: 0` on the AppBar to minimize wasted space
- On smaller screens, icon buttons should use `visualDensity: VisualDensity.compact` or reduced `padding` in `IconButton` to save space

### UI Behavior
- Title text should always be fully visible on phone-width screens (≥320px)
- Title should appear visually centered in the AppBar between leading and trailing icon groups
- Icon buttons are slightly closer together but still easily tappable (maintain minimum 40px touch target)

## Change 3: Document Sorting in DB Screen (מיון מסמכים במסך DB)

### Problem
In the `/db` screen, documents within each collection card are displayed in an arbitrary/unsorted order.

### Scope
Add client-side sorting logic to the DB preview screen so that documents within each expanded collection are displayed in a consistent, meaningful order.

### Sort Logic by Collection

| Collection | Sort Order |
|---|---|
| **teamMembers** | `name` ascending |
| **events** | `startDate` ascending, then `name` ascending |
| **assignments** | `event.startDate` ascending, `event.name` ascending, `role.sortOrder` ascending, `teamMember.name` ascending |
| **checklist_items** | `event.startDate` ascending, `event.name` ascending, `checklistItem.name` ascending |
| **checklist_presets** | `name` ascending |
| All others (utilities, keys, etc.) | No specific sort — keep default Firestore order |

### Files to Modify
- `lib/presentation/screens/db/db_preview_screen.dart` — Add sort logic after fetching documents for each collection, before rendering them in the UI

### Implementation Notes
- Sorting should happen client-side after documents are fetched from Firestore
- For assignments and checklist_items, related entity data (event name, start date, team member name, role sort order) needs to be resolved from the fetched documents or cross-referenced with other collections
- Handle null/missing fields gracefully — documents with missing sort fields should sort to the end

## Change 7: Unified Filter Dialog Behavior (Bottom Sheet + Immediate Apply)

### Problem
Filter dialogs across the app behave inconsistently. The checklist screen's filter dialog has the ideal behavior (enters from bottom, docks to bottom, applies filters immediately without a save/apply button), but the events and assignments filter dialogs use a standard centered dialog with an "apply" button.

### Scope
Make filter dialogs in `/admin/events` and `/admin/assignments` behave like the checklist filter dialog in terms of:
1. **Entrance animation**: Slide up from the bottom (modal bottom sheet style)
2. **Position**: Docked to the bottom of the screen
3. **Immediate filter application**: When the user selects/deselects filter options, the results update immediately on the screen behind the dialog (no "apply" or "save" button needed)
4. **Bottom buttons**: Only "סגור" (Close) and "נקה" (Clear) buttons — no "apply"/"save" button

### Important Constraint
The **internal UI content** of each filter dialog must NOT change. Only the dialog entrance animation, positioning, and filter-apply behavior should change. The category checkboxes, event checkboxes, expandable sections, etc. all remain exactly as they are.

### Files to Modify
- `lib/presentation/screens/event/widgets/category_filter_modal.dart` — Convert from `Dialog` to modal bottom sheet, remove Apply button, wire up immediate filter application via callback
- `lib/presentation/screens/assignment/assignment_filter_modal.dart` — Convert from `Dialog` to modal bottom sheet, remove Apply/Cancel buttons, wire up immediate filter application
- `lib/presentation/screens/event/event_list_screen.dart` — Update how the filter modal is invoked (change from `showDialog` to `showModalBottomSheet`), handle immediate filter state updates
- `lib/presentation/screens/assignment/assignment_list_screen.dart` — Same: update invocation and handle immediate filter state updates

### Reference Implementation
The checklist screen filter (`_showFilterSheet()` in `checklist_screen.dart`) uses:
```dart
showModalBottomSheet(
  context: context,
  isScrollControlled: true,
  backgroundColor: Colors.transparent,
  builder: (context) => Container(
    // Rounded top corners, white background
    // Handle bar at top
    // Filter content
    // Close + Clear buttons at bottom
  ),
);
```

### Behavior Details
- Selecting/deselecting a filter option immediately calls the parent screen's filter update method
- The screen behind the modal bottom sheet re-renders with filtered results while the dialog stays open
- "נקה" (Clear) button resets all filters and immediately shows unfiltered results
- "סגור" (Close) button dismisses the bottom sheet
- No "החל" (Apply), "סינון" (Filter), or "ביטול" (Cancel) button

## Change 11: "Constrained/Unavailable Team Members" Button in Assignment Dropdown

### Problem
In the `/admin/assignments` screen, the dropdown list for each unassigned slot shows available team members and a "שובצו כבר" (Already Assigned) button. There is no way to see or assign team members who have constraints or are unavailable for the event.

### Scope
Add a new button below "שובצו כבר" in the assignment dropdown that shows team members with constraints/unavailability for the event, and allows the admin to force-assign them.

### Files to Modify
- `lib/presentation/screens/assignment/assignment_list_screen.dart` — Add the new button in the dropdown and implement the dialog

### Changes

#### New Button
- Text: `'בעלי מגבלות / לא זמינים'` (Has Constraints / Unavailable)
- Position: Below the existing `'שובצו כבר...'` button in the dropdown
- Style: Similar to the "שובצו כבר" button

#### Dialog Content
When clicked, opens a dialog showing two groups of team members:

1. **Permanent members with constraints** (`isPermanent: true`) — Members who have an approved unavailability constraint (`ConstraintType.unavailability`, `ConstraintStatus.approved`) that overlaps with the event date(s)
2. **Non-permanent members who are NOT available** (`isPermanent: false`) — Members who do NOT have an approved availability entry (`ConstraintType.availability`, `ConstraintStatus.approved`) overlapping with the event date(s)

Both groups are filtered to only show members who have the required role capability for this assignment slot.

#### Assignment Behavior
- Admin can select a team member from this list to assign them to the slot
- The assignment is created normally (same as any other assignment) — the system does NOT block it
- This is an intentional override: the admin explicitly chooses to assign someone despite their constraint/unavailability
- A conflict warning may appear (using existing `hasAvailabilityConflict` logic) but does not prevent the assignment

## Change 12: Alternative Phone Number Field on Assignments

### Problem
When an assigned team member doesn't have a phone number stored in their team member record, there's no way to call them. The admin needs a way to associate an alternative phone number with a specific assignment.

### Scope
Add an "alternative phone number" (`טלפון נוסף`) field to the assignment notes dialog, and update the phone call logic across the app to use a fallback chain.

### Entity Changes

**Modify: `lib/domain/entities/assignment.dart`**
- Add field: `final String? alternativePhoneNumber;`
- Update `copyWith()`, `Equatable` props, constructor

**Modify: `lib/data/models/assignment_model.dart`**
- Add `alternativePhoneNumber` to `toFirestore()` and `fromFirestore()` serialization

### UI Changes

**Modify: `lib/presentation/screens/assignment/assignment_list_screen.dart`** — `_showNotesDialog()` method
- Add a new text field below the existing notes text field:
  - Label: `'טלפון נוסף'` (Alternative Phone)
  - Same validation as the phone number field in the user settings dialog (`PhoneEditDialog`)
  - Uses `Validators.validatePhoneNumber` for validation
  - Uses `PhoneInputFormatter` for input formatting
  - `keyboardType: TextInputType.phone`
  - `textDirection: TextDirection.ltr`
- Save the alternative phone number alongside notes when the user taps "שמור" (Save)
- BLoC event `UpdateAssignmentNotes` should be updated (or a new event created) to also handle `alternativePhoneNumber`

### Phone Call Logic (Fallback Chain)

Update all places where a phone icon/button appears for calling an assigned team member:

**Priority order:**
1. If `teamMember.phoneNumber` is not null and not empty → call this number
2. Else if `assignment.alternativePhoneNumber` is not null and not empty → call this number
3. Else → do not show the phone icon/button

**Files to update with new phone call logic:**
- `lib/presentation/screens/event/widgets/event_assignments_dialog.dart` — Phone icon next to assigned members (line ~254)
- `lib/presentation/widgets/event_team_members_dialog.dart` — Phone icon next to members (line ~402)
- `lib/presentation/screens/assignment/assignment_list_screen.dart` — If there are phone icons in the assignment rows
- Any other location where phone icons appear for assigned team members

### Data Layer Changes

**Modify:**
- `lib/data/data_sources/database_interface.dart` — Update assignment-related method signatures if needed
- `lib/data/data_sources/firestore_database.dart` — Ensure `alternativePhoneNumber` is stored/retrieved
- `lib/data/repositories/assignment_repository.dart` — Pass through the new field

### BLoC Changes

**Modify: `lib/presentation/bloc/assignment/`**
- `assignment_event.dart`: Update `UpdateAssignmentNotes` event to include optional `alternativePhoneNumber` parameter
- `assignment_bloc.dart`: Handle storing the alternative phone number
